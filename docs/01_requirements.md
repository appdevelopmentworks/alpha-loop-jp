# 要求定義

版: 0.1 / 作成日: 2026-09-27 / 状態: 実装開始用設計（売買成績は未検証）

## 1. 目的と完成の意味

日本株について、急騰銘柄の上昇前に観測できた特徴を調べ、翌営業日の監視候補をCSVで出力する。候補だけでなく選外銘柄・失敗例・結果を記録し、仮説を後続期間で検証する。

本システムの完成は「再現可能な抽出と検証ができること」。急騰や利益の保証、実証されていない勝率の達成を完成条件にしない。実装の合格と投資仮説の採用を分ける。

2026-10-03のユーザー再確認: 最終目標には、毎営業日の急騰事例から仮説を立て、その仮説による翌営業日候補を保存し、的中・誤検出・見逃しから次の仮説と条件版を検証する自己改善ループを含む。M0〜M2の基盤完成や固定価格候補の出力だけでは、この最終目標の完成としない。自己改善の対象は仮説・選別条件・採用版であり、モデル重みの追加学習を必須とする要求ではない。詳細と未実装箇所は[21_hypothesis_loop.md](21_hypothesis_loop.md)。

## 3. 実装開始用の既定値

以下は設計上の初期値であり、ユーザー指定や実証済み条件ではない。設定ファイルと版番号で管理する。

| 項目 | 初期値 |
|---|---|
| 市場 | 東証プライム・スタンダード・グロースの普通株、買い方向の調査 |
| 対象外 | ETF・ETN・REIT等。地方単独上場、IPO短期履歴は後続対応 |
| 価格情報 | 日足。指標に必要な過去履歴は最低60取引日 |
| 流動性 | 売買代金の足切りは既定で無効（戦略1.1.0）。売買代金は任意の参考値。旧1.0.0の1億円以上条件は比較用設定として保存 |
| 日次開始予定 | 東証営業日の20:00 Asia/Tokyo。データ提供時刻に応じて変更 |
| 情報締切 | 収集完了後に入力を封印した実時刻as_of。20:00ちょうどとは限らない |
| 主評価 | 翌営業日。3・5営業日先は補助指標 |
| 表示件数 | 監視区分ごと最大20件。全判定は保存。件数不足を無理に補わない |
| 材料AI | 最初は価格条件に影響させず並行評価するshadowモード |
| 外部AI | cloud_enabled=false。外部AIへの自動送信・自動フォールバックは初期無効 |

普通株・取引日・売買停止などは、当時の銘柄一覧と状態から判断する。最新の上場銘柄だけで過去の母集団を作らない。未取得の業種・規模情報を推測で埋めない。

## 4. 日次ループ

上昇後の振り返りも必須の研究ループとする。取引日Dの急騰銘柄をランキング等で発見し、銘柄・掲載時刻・取得時刻・出典を記録する。各銘柄についてD-1以前のデータだけで特徴量と材料を再構成し、同じ時点の全対象銘柄と比較する。Dの値動きやDに初めて公表された材料をD-1の推論入力へ混ぜない。後から取得した履歴は`reconstructed`として、D-1に実際に保存した予測とは区別する。ランキングは事例発見・見逃し確認に用い、ランキング掲載銘柄だけで予測性能を算出しない。

1. 前回候補のうち評価期間が終了したものの結果を記録する。
2. 対象市場の銘柄一覧、カレンダー、日足、取得可能な開示を収集する。
3. 入力を検証してsnapshotを封印し、as_ofを固定する。
4. Pythonで全母集団を計算し、価格・出来高による候補を抽出する。
5. 新規開示も別経路で処理する。価格条件を満たさない未反応銘柄を調査から落とさない。
6. OpenJevで材料を分類し、根拠箇所・判定不能・モデル版を保存する。
7. 価格候補と材料候補を銘柄・イベント単位で統合し、CSV・実行報告を保存する。
8. Qwenによる日報は保存済みの事実を説明する。説明文から数値判定を書き換えない。

翌朝の追加開示確認は後続機能とする。同じ候補を上書きせず別runを作り、寄前に完了しなければ寄前候補として発行しない。

日次・翌朝とも、as_ofと候補の完成時刻が対象とする翌営業日の取引開始より前であることを必須にする。これを超えた実行はlate/history_onlyとして保存し、その日の事前予測成績へ混ぜない。より早い実務上の締切は設定で追加する。

## 5. 初期の価格条件

Dは対象取引日、Cは分割・併合について同一基準へ調整した終値、Hは同様の高値、Vは整合した出来高。休日を数えず、欠損を飛ばして過去窓を短縮しない。

| 指標 | 定義 |
|---|---|
| ret_1d / ret_5d | C[D]/C[D-1]-1 / C[D]/C[D-5]-1 |
| rel_volume_20d | V[D] / mean(V[D-20:D-1])。当日は分母に含めない |
| previous_high_20d | max(H[D-20:D-1])。当日は含めない |
| high_distance_20d | C[D]/previous_high_20d-1 |
| ma25_gap | C[D]/mean(C[D-24:D])-1。当日は含める |

| 区分 | 条件（すべて未検証の仮説） |
|---|---|
| PREMOVE / 未上昇候補 | -0.03 <= ret_5d <= 0.05、rel_volume_20d >= 1.5、-0.05 <= high_distance_20d <= 0 |
| EARLY / 初動候補 | high_distance_20d > 0、rel_volume_20d >= 2、ret_5d <= 0.12 |
| OVERHEATED / 過熱候補 | ret_5d > 0.20 または ma25_gap > 0.15 |
| WATCH / 材料監視 | 対象銘柄の新規開示があり、上記の価格候補に該当しない |
| NONE | 有効データだがいずれにも該当しない |

優先順位はDATA_HOLD（必要データ不足）→INELIGIBLE（対象外）→OVERHEATED→EARLY→PREMOVE→WATCH→NONE。全条件の真偽も別途保持し、単一区分だけで情報を消さない。

OVERHEATEDは既定の候補CSVから外し、全判定記録に残す。戦略1.1.0の監視順位は区分内でrel_volume_20dの降順、銘柄IDの昇順。売買代金の有無・大小で順位を変えない。旧流動性条件を明示的に有効にした比較では相対出来高→売買代金中央値→銘柄IDの順とする。これは表示順であり急騰確率ではない。AIスコアによる順位変更は比較検証後の別ルール版で行う。

| ID | 要求 |

| F02 | 全銘柄の採否と理由を保存し、候補CSV・全判定CSV・結果CSVを出す |
| F03 | 正常な候補ゼロ、休日、データ不備、モデル不調を区別する |
| F04 | 開示の公表時刻、初回取得時刻、訂正履歴を分ける |
| F05 | LLM判定の根拠、質問版、モデル実体、量子化・推論設定を記録する |
| F06 | 過去再構成と実際に当時保存したデータを混同しない |
| F07 | 翌日急騰の発見力と、固定条件の仮想損益を分ける |
| F08 | 仮説の実験版と採用版を分離し、日次実行が本番条件を勝手に変更しない |
| F09 | 急騰事例・非急騰の比較対象・誤検出・見逃しから仮説版を保存し、仮説版を明示した翌営業日の候補CSVと結果CSVを日次で結び付ける |
| F10 | 検証を通った条件版の運用反映と反映後監視・旧版復帰を実装し、自己改善ループを閉じる。初回ACTIVEの人手確認と以降の自動昇格方針を区別し、不十分な場合は現行版を維持する |
| N01 | 通常の計算・保存はLLMなしで動く。AI障害時も基準戦略の出力は可能 |
| N02 | 一重実行、再試行上限、処理段階の再開、原子的な出力確定を実装する |
| N03 | 32GB GPUで両モデルを同時常駐させる前提を置かない |
| N04 | 秘密情報をログ・CSVに書かない。開示本文中の命令を実行しない |
| N05 | 日本語のCSV説明・日報。内部列名は安定した英語snake_caseとする |

データ検証、数値計算、判定器、評価器の実装完了と、材料AIの利用開始を別の段階にする。

## 7. 初期スコープに含めないもの

自動発注、証券口座接続、信用・空売りの売買戦略、リアルタイム板監視、独自モデルの学習、Webダッシュボード、無制限の自律コード変更は対象外。株価や開示の契約・課金はこの設計作成では行わない。

Yahoo!ファイナンス・株探はユーザー指定の急騰事例発見と見逃し確認の入口。自動取得は各提供元の許諾範囲を確認してから接続する。株探は掲載情報の機械的取得を明示的に禁止しているため、許諾のないスクレイピングは実装・運用しない。Yahoo!の公式案内はVIP時系列CSVの私的利用について案内し、それ以外の掲載情報の加工・転載・商用利用を禁止する。ランキング自動取得を有効化せず、手動転記も自動的に許可された方法と扱わない。利用可能な日足CSVから自前の上昇銘柄抽出を先行する。全銘柄の日足履歴と母集団は別途、利用・加工・保存可能な入力を要する。出典と不足列は[11](11_csv_sources_and_plans.md)。材料がないことと、材料の取得経路がないことを区別する。

未決事項・採用判断の記録は[06_decisions_sources.md](06_decisions_sources.md)、実装順は[README.md](README.md)を参照。

## 8. Hermes運用への追加指定（2026-09-30）

ユーザーはHermesで運用できる状態まで進めることを指定した。uv管理を維持し、追加CSVの手動提供を日次処理の前提にせず、取得できる情報で候補・前日比較・翌日評価を実行する。スタンダード・グロースを先に取得しプライムを含める優先順は設計初期値で、市場別分母・未知件数・急騰件数を保存する。特定市場に急騰が多いという仮説は検証済みと扱わない。取得方法、定時起動、研究用データの制限は[12](12_hermes_operation.md)。
