# M5次フェーズ: 日次の仮説ドリブン自己改善

更新: 2026-10-03。ユーザーが再確認した最終目標と、実装した日次自己改善機能を記録する。合成でループ・採用・復帰を確認し、実データによる採用と新版の次回定時は未確認。[要求](01_requirements.md) / [構成](02_architecture.md)。

## 1. 必須の日次サイクル

取引日Dと前営業日D-1、翌営業日D+1を使う。

1. Dに高上昇率だった銘柄を取得可能な日足から特定する。
2. それらのD-1までの状態と、同時点の非急騰銘柄を比較する。前日に出した候補の的中・誤検出と、候補外の実急騰も保存する。
3. Qwenが利用可能な観測事実から改善仮説を提案し、Pythonが有限の条件定義へ変換・検証する。仮説・出典・参照期間・条件・版を保存する。
4. Dまでに利用できた情報を使い、凍結した仮説版でD+1向けの候補CSVを発行する。基準戦略と未採用仮説は別run/別CSVで保持する。新仮説も翌営業日にshadow候補を出せることを要件とする。
5. D+1の結果が確定したら、その時点で封印した候補を評価する。仮説ごとの的中率、捕捉率、誤検出、見逃し、件数、不明・欠損を記録する。
6. 更新可能な開発用観測を次の仮説へつなぐ。旧版を上書きせず、新版として候補・比較を継続する。
7. 未使用期間の固定比較で合格した版を、決められた採用手順で運用へ反映する。反映後監視、停止、旧版復帰まで閉じたループにする。

休日は営業日カレンダーに従う。仮説生成が失敗・無根拠・重複・上限到達なら既存版を維持し、毎日新条件を無理に作らない。初回ACTIVEは既存設計の人手確認を保持し、以降の有限な自動昇格ルールは版付き設定で実装した。ポリシーを変える場合は新しい基準への人手確認が必要。

## 2. 実装した接続

| 部分 | 再確認前 | 今回の実装 |
|---|---|---|
| 急騰銘柄の前日状態 | 日次ランキング相当・retrospective保存あり | 価格基準と仮説別の的中・誤検出・見逃し・不明を全母集団で保存 |
| 仮説案 | 日次Qwen案、金曜の下書き整理あり | 開発用結果をQwenへ渡し、有限カタログの条件版を保存。重複をまとめ、既定最大8版・1日最大2案 |
| 翌営業日候補 | 固定価格基準で日次出力 | 仮説ごとのANDフィルター候補、選外理由、次営業日、時点・版・hashを別CSVで保存 |
| 比較・採否 | 固定比較・報告・人手shadowレビューあり | 新仮説を未使用期間へ自動登録。既存価格M5で比較し、初回人手確認・後続の固定基準による昇格へ接続 |
| 運用条件 | ACTIVE切替なし | 設定上書きを伴わない版ポインター、運用候補CSV、監視・旧版復帰、hash連鎖の変更履歴 |

固定価格候補にQwenの説明が付くだけでは、このサイクルの完成としない。モデル重みの追加学習は現スコープ外。改善する対象は仮説・条件・採用版である。

今回の数値仮説は既存価格M5と同じ「価格基準の候補へのANDフィルター、補充なし」。基準候補の外への追加は材料B2の別比較を使い、この価格昇格で検証済みと扱わない。見逃しは候補外も保存し、条件を緩めた次版や基準へ戻す判断の入力にする。条件カタログ外の指標探索・自由なコード生成・無制限の試行は含めない。

## 3. 比較とデータの契約

- Dの急騰を説明する入力はD-1以前に限定する。D+1候補にはDまでの情報を使える。仮説生成・候補完成はD+1の取引開始前に完了し、遅れたものは事前予測成績に入れない。
- 成績は発行済みの版と候補で計算する。後日の仮説で過去候補を作り直した成績は再構成研究として分ける。
- 毎日の改善に使う開発データと、採否の最終評価データを分離する。登録済み実験の保護期間を提案へ漏らさず、条件・期間・数値エンジンを変更しない。結果を見た期間を新たな未使用期間として再利用しない。
- 的中率だけで候補を極端に減らさない。全母集団に対する捕捉率・候補数・不明率も比較する。価格上昇と費用・未約定を含む収益は別指標。
- reconstructed/合成、実材料の品質不足、件数不足では本番昇格を保留する。日次shadow候補の発行と本番採用は別の時点になる。
- AIの自由なコード編集や本番設定の直接上書きは行わず、検証可能な有限条件をPythonで処理する。外部AI送信・発注は無効を保持する。

## 4. 実装の受入条件

合成の複数営業日で、急騰前比較→仮説版→翌日shadow候補→的中/誤検出/見逃し→次版まで自動でつながる。再実行一致、仮説の重複、将来情報拒否、休日、候補ゼロ、欠損、AI失敗でも基準出力維持、未使用期間の再利用拒否を試験する。

合格版だけの切替、同時切替の排他、中断復旧、不合格/HOLD時の現行版維持、採用版が悪化した時の停止/旧版復帰、旧版の再現を合成で試験する。実資料品質・実未使用期間による採用判断は別ゲートとして記録する。

## 5. 工数とデータ待ち

会話で提示した8〜12人日は、既存機能を利用した残実装・試験・文書の暫定概算。詳細実装時に日次世代管理・採用ポリシー・障害復旧の差分から更新する。着手日や実データ採用日を確約する値ではない。

データ蓄積を待たず、合成データでループ・監視・復帰を実装できる。既存価格2実験の12月1日以降という日付は、その固定比較が可能になる最初の目安。50日分を集めるだけで実装が完成したり、自動昇格が許可されたりする意味ではない。

## 6. 実行と成果物

標準ライブラリだけの隔離合成確認（[18のuv環境](18_setup.md)を設定後）:

```powershell
uv run --offline --managed-python --no-project --python 3.11 python -S scripts/verify_self_improvement.py
```

`data/si/<ID>/`へ合成の複数営業日・2仮説版、候補/結果、固定比較、初回明示採用、悪化時の自動復帰、次版の自動採用を作る。模擬reasonerと独立したsynthetic比較を使用し、productionポインターはnull。証跡は`data/operations/self_improvement_acceptance.json`。合成の人名・レビューは利用者の実承認ではない。

自己改善付きの日次入口:

```powershell
uv run --offline --managed-python --no-project --python 3.11 python -m alpha_loop.cli operate --operation-config configs/hermes_self_improving.json
uv run --offline --managed-python --no-project --python 3.11 python -m alpha_loop.cli self-improve-status
```

Hermes配置用ラッパーの既定も`configs/hermes_self_improving.json`。2026-10-03に配置済み入口とskillを同期し、隔離合成の実ラッパーを確認した。明示的な`ALPHA_LOOP_CONFIG`は優先する。従来の`configs/hermes_operations.json`は変更せず残し、従来CLIを再現できる。個人設定は新設定を元に`.local.json`へ作成する。ファイル入力のカレンダーには、判定日Dに加えて翌営業日D+1が必要。

| 保存先 | 内容 |
|---|---|
| `data/self_improvement/state.sqlite` | 仮説版・発行前intent・完成日・評価・研究登録・採用履歴のhash付き台帳 |
| `outputs/self_improvement/hd-*/candidates.csv` | version_id付きの各仮説shadow候補。複数版なら同じ銘柄の行が複数ある |
| 同ディレクトリの`decisions.csv` / `selections.json` | 全銘柄の条件判定・選外理由と凍結した選択 |
| 同ディレクトリの`active_candidates.csv` | 採用版の運用候補。未採用なら空で、日次結果の`operational_candidate_csv`は基準CSVを指す |
| 同ディレクトリの`evaluation/` | 全母集団の版別結果、HIT/FALSE_POSITIVE/MISS/UNKNOWN、比較集計 |
| `data/self_improvement/plans/hv-*/` | 仮説版の固定条件・calendar・基準設定と価格M5への登録 |
| `outputs/research/exp-*/` | 既存価格M5による未使用期間の比較・HOLD/REJECT/採用候補 |

既存の`outputs/<run>/candidates.csv`は基準として保存し続ける。運用に使うCSVは日次結果の`operational_candidate_csv`で確認する。

初回の本番採用は、prospectiveの合格比較と対応する時点内shadow記録が揃ってから、人が行う:

```powershell
uv run --offline --managed-python --no-project --python 3.11 python -m alpha_loop.cli self-improve-activate --experiment-id <exp-ID> --reviewer <名前> --human-reviewed
uv run --offline --managed-python --no-project --python 3.11 python -m alpha_loop.cli self-improve-monitor --session <YYYY-MM-DD>
uv run --offline --managed-python --no-project --python 3.11 python -m alpha_loop.cli self-improve-rollback --reason <復帰理由>
```

初回人手記録後の自動昇格は`automatic_promotion=true`の固定ポリシー、当該版自身の登録比較・同じpolicy・未退役版だけ。holdout全日の取引開始前に完成した仮説別候補とhashが必須。別ポリシーへの承認は引き継がない。1回の処理で最大1昇格。採用済み比較の使い回しで版を往復させない。rollbackは前採用版、最初なら価格基準へ戻す。

監視の初期値は直近20日・最低5日/選択50件、不明率20%以下、基準との差で的中率5ポイント・捕捉率5ポイント超の悪化で復帰。採用時のポリシーを固定し、監視基準を後から緩めない。これは取引収益の損切りや金融的な最適値ではない。

中断は封印intentから復帰する。同一日で入力・policy・ソースを変更したら拒否する。仮説生成や自己改善の失敗は基準CSVを保持して`SUCCEEDED_WITH_SIDE_FAILURE`へ記録し、原因解消後の同じ入力の再実行で再試行できる。

## 7. 実運用の残ゲート

実機Qwenによる新版feedbackプロンプトの定時完了、実未使用期間・提供元完全性・真正PIT品質、実資料の人手正解は未検証。新しい日次の初回は既存Hermesジョブの次回営業日。GPU設定・モデル・定時ジョブの追加登録は行わない。

現在の入力はreconstructedのため、実際の仮説版は研究/shadowで運用し、本番昇格はHOLD。登録中の最終期間を提案へ渡さず、保護期間中は新案を採らず既存版の候補と評価を継続する。未知・候補ゼロ・同じ案の反復・試行枠到達も正常な継続状態。

8〜12人日は事前の暫定見積であり、今回の実作業時間や残工数の測定ではない。有限な価格仮説ループの機能実装と、実データでの運用採用を分けて報告する。
