# 仮説の前の分析・推論工程

更新: 2026-10-04。ユーザー指定により、比較集計から直接条件を選ぶ経路へ、独立したローカルQwenの分析工程を追加した。[自己改善ループ](21_hypothesis_loop.md)の仮説生成に接続する。

実施結果: 全240テスト成功、標準ライブラリの隔離合成と新規配置先での一周が成功。既存ローカルQwenでも保存済み10/2事例を使う分析→仮説が成功し、元の数値成果物とモデル状態を保持した。Hermes配置を確認済み。新しい定時全工程と実翌日フィードバックは次回以降の確認。詳細は04§21。

## 1. 処理順序

1. Pythonが急騰銘柄と対照群の前営業日時点の指標、観測件数、比較方向を計算する。開発用の的中・誤検出・見逃しも参照できる。
2. **Qwenの1回目**で、観測の根拠ID、考えられる説明、代替説明、反証条件、未校正の確信度を選択する。これは短い分析要約で、観測数値はPythonが確定する。
3. Pythonが根拠の存在・時点・対応する指標・応答の完了・モデル/版を検証し、分析成果物を保存する。
4. **Qwenの2回目**へ検証済みの分析を渡し、分析に根拠がある指標の有限AND条件から仮説を提案する。Pythonが条件・単位・閾値・根拠との対応を検証する。
5. 保存した分析manifestのhashを仮説応答と世代に結び、翌営業日候補・評価・比較・採用へ進める。

Qwen/Qwen3.8-27B由来の既存Inferact NVFP4・固定revision・RTX 5090の構成を使う。新モデルのダウンロードは不要。構造化した分析要約を独立した応答として保存するため、`enable_thinking=false`は維持する。モデルの非公開の思考過程を要求・保存する機能ではない。

## 2. 設計上の初期値と制限

観測IDは`obs:<feature>`、既存仮説の開発用結果は`feedback:<version_id>`。前日群中央値を個別銘柄の数値へ転用しない。掲載されていないことを陰性とせず、不明・未取得を事実として補わない。

説明は出来高、高値との位置、直近騰落、移動平均乖離の4種類。代替説明は市場/業種要因、少数標本、未観測材料、選別の偏り。反証条件は的中改善なし、捕捉悪化、日/銘柄を変えた時の不安定性。これらは有限カタログの初期値であり、因果関係や有効性の確定ではない。分析1〜4件、根拠1〜4件、代替/反証各1〜2件、確信度low/moderate。モデルが新しい数値や自由なコードを作ることは認めない。

分析入力は最大16KB、分析応答は最大1,536tokens、仮説応答は従来の1,024tokens。分析付き仮説入力は最大20KB。モデル1呼出しの既存timeout=300秒、GPU排他・復元と監督の有限予算を維持する。再実行は保存済み応答を検証して再利用する。

根拠不足なら`INSUFFICIENT_EVIDENCE`を保存し新仮説を生成しない。途中切れ・未知ID・根拠と指標の不一致・未来の評価・変更された成果物は拒否する。分析が仮説判定時点より後に完成した場合も新世代へ使わない。分析失敗時は価格基準CSVを残し、AI失敗として記録する。成功した分析の後で仮説生成が失敗した場合、分析を再利用して仮説側を再試行する。

登録済み最終期間のランキング日または前日特徴日は、分析・仮説のモデル入力に渡さない。日次、CLI、低水準の分析付きレポート入口で拒否する。その期間も既存の凍結版による候補発行と評価は継続する。

## 3. 保存と実行

`outputs/retrospectives/<study>/inference/<analysis-id>/`に次を保存する。

| ファイル | 内容 |
|---|---|
| `input.json` | Pythonの観測値・根拠ID・時点・grade・コード定義 |
| `response.json` | ローカルQwenの原応答 |
| `analysis.json` | 検証済みの分析要約 |
| `report.md` | 根拠・説明・代替説明・反証条件をPythonが表示したレポート |
| `manifest.json` | 入力/成果物hash、モデル/revision/runtime、生成設定、ソースbundle、完成時刻 |

仮説レポートの`inference`、キャッシュfactsの`pre_hypothesis_analysis`、世代のsourceから追跡できる。要求・入力・成功/失敗履歴は`data/operations/qwen_attempts/`にも保存する。価格/前日特徴/既存応答は上書きしない。

Hermesの既存入口`configs/hermes_self_improving.json`とCLIの`retrospective-report`は、この工程を必須にする。追加の定時ジョブ登録は不要。低水準関数の`analysis_required=False`は旧形式の互換・試験用に残すが、新しい自己改善世代は分析のない提案を拒否する。登録済みの価格M5 2実験は従来の凍結エンジンと原本を保持する。

合成で一周を確認（[uv環境設定](18_setup.md)の後）:

```powershell
uv run --offline --managed-python --no-project --python 3.11 python -S scripts/verify_inference.py
```

隔離した15営業日の分析・2仮説版・候補/翌日結果・固定比較・模擬採用/復帰を作る。成果物の位置は`data/operations/inference_acceptance.json`。API・GPU・追加パッケージなし。実データ・実LLMの品質検証ではない。

実機確認用の`python scripts/verify_inference_local.py`は保存済み直近の事例を既存Qwenで処理する。実日次処理中は拒否し、GPU排他・元状態復元を使用する。新しい収集や予測CSVの発行は行わず、過去事例の研究応答として記録する。

## 4. 残る検証

合成の構造試験と、実機で正しい形式の応答が返ることは別に記録する。実市場での説明の妥当性・条件の改善性能、取得できていない材料や業種要因は未検証。分析の追加から因果関係や予測精度を推定しない。採用は従来の未使用期間・品質・初回人手確認に従う。実施結果は[04の検証記録](04_validation.md)に記載する。
